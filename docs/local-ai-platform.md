# 本地 AI 平台运维与用户指南

本文面向使用 Web UI 部署本地模型的用户，以及负责安装、升级、备份和排障的运维人员。文档中的能力以当前服务端实现和运行时探测结果为准。

## 适用范围

- 发布产物覆盖 Windows x64、Linux x64 与 Linux ARM64，不包含 Android 客户端。Android 当前仅保留数据契约，不提供客户端、安装包或完整部署路径。
- 本地对话使用 ONNX Runtime GenAI；Embedding 与 Reranker 使用标准 ONNX Runtime。市场模型不会捆绑进发布产物，需由用户下载。
- Web UI 的「本地部署」页面统一管理部署、模型市场、已安装模型、算力设备和下载任务。
- 云端、本地和自定义 Provider 由「模型接入」页面统一配置；本地模型管理与 Provider 凭证管理是两个独立入口。

## 上线前检查

1. 按 [安装部署说明](../SETUP.md) 完成依赖安装并复制 `.env.example` 为 `.env`。
2. 确认模型盘有足够可用空间，服务进程对目标目录具有创建目录、写入临时文件和重命名文件的权限。
3. 当前仅支持公开 ModelScope 仓库，无需也不应在 `.env` 配置 ModelScope 访问凭证；受限仓库暂不支持。
4. 启动服务并观察终端或服务日志：

   ```bash
   python agent.py --web
   ```

5. 登录 Web UI，进入「本地部署」→ `算力设备`，点击「重新扫描」，确认至少存在可用 CPU 和健康的运行提供程序。
6. 首次上线建议先下载小体积模型，完成下载、启动、停止和重启恢复验证后再开放给用户。

## 用户操作指南

「本地部署」包含五个标签：

| 标签 | 用途 | 常用操作 |
| --- | --- | --- |
| `部署` | 查看运行中实例，并从已安装模型创建实例 | 选择设备后「启动」，对运行实例执行「停止」 |
| `模型市场` | 按名称或用途筛选精选模型 | 「查看并下载」、选择存储目录、确认模型详情 |
| `已安装` | 查看模型目录、revision、用途、所有权和校验状态 | 对可移除的用户模型执行「移除」；内置模型不可移除 |
| `算力设备` | 查看后端实际探测到的 CPU、GPU、NPU 和运行提供程序 | 「重新扫描」并检查设备状态、内存和后端健康状态 |
| `下载任务` | 查看进度、速度、预计时间和错误 | 对任务执行「暂停」「恢复」「取消」；完成后可直接「启动」 |

推荐首次使用顺序：

1. 在 `算力设备` 重新扫描并确认设备可用。
2. 在 `模型市场` 选择 Chat、Embedding 或 Reranker 模型，点击「查看并下载」。
3. 选择服务器上的模型目录；需要以后复用时勾选「保存为默认目录」。
4. 在 `下载任务` 等待校验完成。任务失败时先查看错误，不要直接移动 `.part` 文件。
5. 在 `部署` 选择匹配设备并启动实例，状态健康后再切换业务路由。
6. 停止正在使用的实例后，才在 `已安装` 移除对应用户模型。

## Provider 接入

「模型接入」向导支持四类协议：

- `openai`：OpenAI 兼容接口，可用于 SiliconFlow、ModelScope、OpenRouter 等服务。
- `anthropic`：Anthropic Messages 兼容接口。
- `ollama`：本机 Ollama 的 OpenAI 兼容端点，建议使用回环地址，例如 `http://127.0.0.1:11434/v1`。
- `custom-map`：自定义请求映射，仅使用受支持的 `{api_key}`、`{base_url}` 等模板变量。

接入流程为「填写配置 → 测试连接 → 保存」。测试成功后才保存 Provider；保存失败会回滚本次接入，避免留下不完整配置。API Key 不应写入 README、日志、截图或模型目录；生产环境应限制 `.env` 和配置目录的读取权限。

### ModelScope 来源策略

- 本地模型市场以 `config/local_model_catalog.json` 的精选 ModelScope 清单为准，不在运行时接受任意仓库地址。
- 当前仅支持公开 ModelScope 仓库，不发送访问凭证；受限仓库暂不支持。每个模型都必须固定到 7–64 位十六进制不可变 `revision`；`main`、`master`、`latest` 等可变引用会被拒绝。
- 每个文件都声明大小和 SHA-256，模型总下载大小必须等于文件大小之和。
- Chat 模型要求 ONNX Runtime GenAI 清单；Embedding 与 Reranker 要求相应 ONNX 文件。
- 普通市场查询默认只展示不超过 5 GiB 的模型；高级查询可解除展示上限，但仍需满足存储和完整性校验。

## 模型存储

- Web UI 提示输入服务器绝对路径，便于用户明确目标位置；API 仍会接受相对路径，并以服务进程当前工作目录为基准规范化为绝对路径。路径穿越、逃逸符号链接以及 `/dev`、`/proc`、`/sys` 下的特殊路径不可作为下载目标。
- 下载前检查目录能否创建、是否可写以及可用空间是否覆盖模型下载大小；失败时 Web UI 会显示「目录不可写」或「空间不足」等原因。
- 仅选择并验证目录不会自动保存为默认目录。只有勾选「保存为默认目录」并确认后，才持久化 `local_ai.default_model_root`。
- 默认目录在每次下载前都会重新校验。目录被卸载、改为只读或空间不足时，系统要求重新选择，不会盲目复用旧路径。
- 用户下载的模型登记为用户所有，可在确认后移除；内置模型及不允许移除的模型不会显示移除操作。当前移除只删除已安装模型登记，不会删除模型目录或其中的文件；需要释放磁盘空间时，运维人员应在确认目录未被其他模型或任务共用后另行清理。

## 下载与恢复

- 下载支持 HTTP Range 断点续传，未完成文件使用 `.part` 后缀。暂停保留分片；取消时可选择保留分片或丢弃分片；恢复会从服务端确认的偏移继续。
- 每个文件完成后执行 SHA-256 校验。校验失败的文件移入目标目录下的 `.quarantine`，任务状态变为隔离，不会注册为已安装模型。
- 下载任务状态原子写入数据目录下的 `local_ai_downloads.json`。运维备份时应同时保存该文件和模型目录。
- 服务启动会读取状态文件并重新计算已有文件和分片大小。重启前处于下载中的任务会恢复为暂停状态，由用户确认后点击「恢复」，避免启动瞬间自动占满带宽。
- 不要手工编辑 `local_ai_downloads.json`，也不要在任务运行时移动目标目录；需要清理时先取消任务并停止服务。

## 运行时与路由

支持的组合如下：

| 用途 | 运行时 | 必要文件或条件 |
| --- | --- | --- |
| Chat | ONNX Runtime GenAI | 模型目录包含有效 `genai_config.json` |
| Embedding | ONNX Runtime | 模型目录和输入输出契约通过校验 |
| Reranker | ONNX Runtime | 模型目录和重排输入输出契约通过校验 |

启动实例时可以显式选择设备；未指定设备时由设备注册表选择兼容且健康的后端。显式选择的本地实例不可用、设备失联或运行时校验失败时，系统返回明确错误，不会静默回退到云端。未选择本地实例时，原有云端 Provider 路径保持不变。

## 算力设备证据

- 页面只展示后端探测结果，不根据 UI 文案推断硬件。CPU、GPU、NPU 的型号、内存、架构和运行提供程序均来自系统或运行时证据。
- Linux 证据可能来自 `/proc/cpuinfo`、设备树、系统内存信息、ONNX Runtime provider 和 NPU 驱动探测；Windows 使用系统接口与可用的运行提供程序。
- 「重新扫描」会强制刷新设备记录。设备存在不等于运行时健康，应同时检查设备状态和 backend 健康标记。
- 文档和界面不写死任何设备型号或 TOPS 数值。NPU 能力以当前机器、驱动和运行时实际探测证据为准。

## 日常运维

- 每日检查：失败或隔离的下载任务、降级实例、剩余磁盘空间，以及设备 backend 健康状态。
- 变更前：停止受影响实例，暂停下载，备份配置、数据库、`local_ai_downloads.json` 和用户模型目录。
- 变更后：重新扫描设备，恢复下载，逐个启动实例并执行最小推理检查；不要一次恢复全部大模型。
- 容量管理：为 `.part` 分片、`.quarantine` 隔离文件和模型解包预留空间。确认无排障价值后再离线清理隔离文件。
- 日志排查：先记录操作时间、模型 ID、任务 ID、实例 ID、设备 ID 和界面错误，再检查服务日志；不要在工单中附带明文凭证。
- 文档契约自检：

  ```bash
  .venv/bin/python -m pytest tests/test_local_ai_docs_contract.py -q
  ```

## 故障排查

| 现象 | 检查顺序 | 处理建议 |
| --- | --- | --- |
| 本地 AI 资源加载失败 | 登录状态、服务启动日志、Local AI 服务初始化 | 刷新页面；确认服务未返回 503；修复初始化错误后重启 |
| 目录不可写 | 路径是否存在、服务账户权限、是否为符号链接或系统特殊路径 | 改用普通数据目录并重新验证，不要放宽整个磁盘权限 |
| 空间不足 | 页面显示的 required bytes、目标卷剩余空间、`.part` 与 `.quarantine` 占用 | 释放空间或选择新目录，保留足够校验与恢复余量 |
| 下载中断 | 网络、任务错误、`.part` 大小、远端是否支持 Range | 先点「恢复」；反复失败时取消但保留分片，排除网络后重试 |
| 校验失败 | revision 是否变化、文件 SHA-256、代理或缓存是否篡改内容 | 保留 `.quarantine` 供核验，重新下载；不要手工注册模型 |
| 设备不可用 | 重新扫描结果、驱动、ONNX Runtime provider、设备内存 | 修复驱动或改选健康设备；不要依据固定 TOPS 文案判断 |
| 实例启动失败 | 模型 validation state、用途与运行时组合、设备状态、模型目录 | 按错误修复清单或权限；确认模型与设备匹配后重新启动 |
| 本地实例中途降级 | 设备热拔插、健康检查、模型目录挂载 | 停止实例，恢复设备或目录后重启；系统不会静默切云端 |

## 安全与备份

- Provider 凭证只存放在受限的环境或配置存储中；备份必须加密，恢复后应检查文件权限并轮换可能暴露的 Key。
- 模型下载仅信任精选清单中的不可变 revision 和 SHA-256。不要用未知文件覆盖已校验模型，也不要绕过隔离状态。
- 备份至少包含 Web UI 配置、主数据库、`local_ai_downloads.json` 和用户模型目录。备份前停止实例并暂停下载，确保状态文件与磁盘内容一致。
- 恢复顺序为配置和数据库、下载状态文件、模型目录；随后启动服务、重新扫描设备、检查已安装模型校验状态，最后逐个恢复下载和实例。
- 移除用户模型登记前，先确认没有运行实例和业务路由引用。该操作不会清理磁盘文件；如需删除模型目录，应在备份并确认目录未被其他模型或下载任务共用后，通过受控的文件运维流程处理。

# WebUI 体验优化设计

## 背景

当前 WebUI 已覆盖聊天、Agent、模型、本地部署、工作目录与终端等主要能力，并形成草元素暗绿玻璃拟态的统一方向。本轮不整体重做主题，而是解决影响日常使用的交互断点、响应式缺口、视觉不一致和性能叠加问题。

## 目标

- 优先建立完整、可信、可恢复的交互反馈闭环。
- 保留现有视觉辨识度，统一关键组件的层级和状态表达。
- 以桌面端为主要验收环境，同时保证触屏和小屏基本可用。
- 控制模糊、粒子、阴影、鼠标跟随和转场的叠加成本。
- 不改变核心业务能力和用户已有操作习惯。

## 非目标

- 不整体替换现有主题或设计语言。
- 不新增与体验优化无关的业务功能。
- 不通过统一关闭全部视觉效果来换取性能。
- 不以固定超时或隐藏错误掩盖异步任务和连接问题。

## 优化策略

采用体验闭环优先的渐进精修：先修复静默失败、错误成功提示和不可执行状态，再处理导航、响应式、视觉一致性、动效性能和无障碍语义。各项修改保持局部、可验证，避免大范围页面重写。

## 交互闭环

### 聊天与附件

- 图片或文档存在时允许不输入附加文本直接发送。
- 不支持的文件类型、上传失败和上传中断显示明确原因。
- 发送按钮根据文本、附件、上传状态、生成状态和连接状态计算可用性。
- WebSocket 未连接时保留用户输入，并显示连接状态和重试动作。
- 消息记录保留搜索、深度思考、图片和文档上下文，重试时完整重放原始请求。

### 异步任务

- 明确区分已提交、排队、执行中、成功、失败和已取消状态。
- 接口接受任务只提示已提交，不使用成功文案。
- 后台启动失败必须通过实时事件或状态查询回到界面。
- 失败状态包含可理解原因和可执行的重试入口。

### 初始化与错误

- 首次运行检测失败与正常未配置状态分开展示。
- 关键请求错误统一采用可见反馈，不静默清除用户选择或输入。
- 错误信息不暴露密钥、令牌、完整内部堆栈或敏感路径。

## 导航与响应式

- 桌面侧栏保留悬停展开，并增加显式固定与收起能力。
- 导航项按使用场景分组，保持现有路由不变。
- 当前页面具有清晰激活态、图标说明和键盘焦点。
- 触屏和小屏使用菜单按钮打开侧栏，通过遮罩、返回键或选择导航项关闭。
- 内容区、弹窗和聊天输入区避免被固定导航遮挡。

## 视觉系统

- 延续草元素暗绿玻璃拟态、嫩芽和翡翠强调色。
- 使用现有设计令牌统一弹窗、选择器、卡片、状态标签和空状态。
- 移除与暗色主题割裂的硬编码浅灰背景及边框。
- 后端英文枚举通过集中映射展示为一致的中文状态文案。
- emoji 只作为辅助视觉，不承担唯一的操作含义。
- 加载、空数据、失败、禁用和成功状态使用一致的信息层级。

## 动效与性能

- 动效只用于表达页面切换、状态变化、任务进度和操作确认。
- 首屏优先完成可交互内容，再启用粒子、定制光标等装饰层。
- 避免同一区域同时叠加高模糊、大阴影、粒子和持续变换。
- 延续设备能力检测，并将降级集中为可解释的效果组合。
- 尊重 `prefers-reduced-motion`，关闭非必要位移、旋转和拖尾。
- 不降低输入、滚动、菜单和发送等核心交互的响应优先级。

## 无障碍

- 图标按钮提供可读名称和可见键盘焦点。
- 斜杠菜单采用正确的列表、选项、选中态和展开态语义。
- 连接变化、上传失败和异步任务结果通过非打断式状态区域播报。
- 主要点击目标在桌面和触屏环境均保持合理尺寸。

## 模块边界

- 输入组件只负责草稿、附件和发送意图，不直接承担全局错误策略。
- Chat Store 保存可重放的消息请求，并返回结构化发送结果。
- WebSocket 层只负责连接、发送和事件分发，连接反馈由 UI 状态消费。
- 通用状态反馈通过既有 Naive UI Provider 和统一映射呈现。
- 响应式侧栏状态由布局层管理，路由定义保持纯配置。
- 性能策略集中在 UI Store 和根效果层，避免组件各自判断设备能力。

## 数据流

1. 用户输入文本或添加附件，输入组件形成完整请求草稿。
2. 输入组件检查上传、生成和连接状态，提交发送意图。
3. Chat Store 调用 WebSocket，确认发送成功后追加用户消息。
4. 发送失败时保留草稿并返回结构化原因，由界面显示反馈。
5. 服务端事件更新流式消息、工具状态和异步任务状态。
6. 重试从原消息请求快照恢复全部模式和附件上下文。

## 验证

- 运行前端类型检查和生产构建。
- 运行现有前端运行时、本地 AI 和相关后端测试。
- 补充附件独立发送、连接失败、重试上下文和响应式导航契约测试。
- 使用真实浏览器检查登录、聊天发送、附件失败、断线、任务失败、侧栏和小屏布局。
- 检查正常动态和减少动态两种系统偏好。
- 检查控制台错误、失败网络请求和关键交互期间的明显卡顿。

## 完成标准

- 不再存在已识别的关键静默失败路径。
- 附件可独立发送，发送失败不会丢失草稿。
- 异步任务不会把已接受错误呈现为已完成。
- 桌面侧栏和小屏导航均可通过鼠标、触屏和键盘操作。
- 关键弹窗和状态组件与现有主题一致。
- 前端构建、相关测试和浏览器主流程验证全部通过。

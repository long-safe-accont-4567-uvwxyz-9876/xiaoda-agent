# CLI 下拉命令面板设计文档

> 主题：CLI 斜杠命令交互重构 —— 下拉命令面板
> 日期：2026-08-06
> 状态：已确认方向

## 1. 背景与问题

当前 CLI（[cli.py](file:///home/orangepi/ai-agent/cli.py)）的斜杠命令交互存在明显缺陷：

1. **命令不自动弹出** —— 输入 `/` 后无即时反馈，需手动敲完整命令名或按 `Tab` 补全，体验差。
2. **视觉不统一** —— 补全下拉与多步菜单（`select_from_menu`）样式割裂，与整体纳西妲美术风格不统一。
3. **命令混乱难找** —— 命令数量多（20+），无分组、无搜索，用户难以发现可用命令。
4. **多步命令不人性化** —— `/model`、`/agent` 等多步命令需先敲完整命令再回车才弹菜单，步骤割裂。

用户参考了 MiMo Code（Mimocode）的交互形态：输入 `/` 立即弹出命令面板，列出命令+描述，方向键选择、回车执行，多步命令直接进入二级选择。

## 2. 设计目标

- 输入 `/` 的**瞬间**弹出命令面板，无需手动敲完整命令、无需 `Tab`。
- 命令面板**不分主人/公共**，统一列出全部命令，每条 `命令名 + 描述`，当前项高亮。
- 面板内可**实时过滤**、方向键选择、回车执行。
- 多步命令在**面板内**进入二级菜单，一气呵成，不误发裸命令。
- **保留现有 prompt_toolkit + 纳西妲美术风格**，不引入 Textual（此前已因"太丑/割裂感"回退 Textual 全屏 TUI）。

## 3. 方案选择

| 维度 | 选择 | 理由 |
| --- | --- | --- |
| 面板形态 | 下拉命令面板（非全屏） | 最贴近 Mimocode，改动聚焦，无全屏割裂感 |
| 面板与输入框关系 | 输入行 + 面板一体 | 输入 `/` 即弹出，方向键兼顾移动，无缝切换 |
| 多步命令 | 面板内二级菜单 | 选中后面板刷新为二级选项，全部选完才执行 |

## 4. 交互设计

### 4.1 命令面板触发

- 输入框内输入 `/` 的瞬间（`text` 变更且以 `/` 开头），输入框上方渲染命令面板。
- 面板内容随输入动态过滤：
  - 输入 `/m` → 过滤出 `/model`、`/memory` 等以 `m` 或匹配的命令。
  - 输入 `/model `（尾随空格）→ 进入该命令的参数级补全/二级菜单。
- 输入不再以 `/` 开头（删除 `/`）→ 面板自动关闭，回到普通聊天输入。

### 4.2 面板内容与排版

- 不分主人/公共，统一列出全部命令（`COMMAND_DESCRIPTIONS`）。
- 每条：`命令名`（左对齐，固定宽度）+ `描述`。
- 当前项高亮（`reverse` 或 `叶子绿` 前景）。
- 底部提示栏：`↑/↓ 选择 · Enter 执行 · Esc 关闭`。

### 4.3 键盘操作

| 按键 | 行为 |
| --- | --- |
| `↑` / `k` | 面板打开时：上移选择 |
| `↓` / `j` | 面板打开时：下移选择 |
| `Enter` | 面板打开且选中多步命令 → 进入二级菜单；选中单步命令 → 执行；面板关闭 → 发送普通消息 |
| `Esc` | 面板打开 → 关闭面板回普通输入；多步二级菜单 → 取消，不误发裸命令 |
| `Tab` | 沿用补全（兜底） |

### 4.4 多步命令（面板内二级菜单）

- 选中 `/model` → 面板切换为 secondary 列表：provider 列表 → 选中后刷新为该 provider 的模型列表 → 选中后拼接完整命令执行。
- 选中 `/agent` → 面板切换为代理列表 → 选中后执行。
- `/voice`、`/doctor`、`/cost`、`/cam` → 面板切换为固定参数列表（`on/off`、`json/fix`、`7d`、`snap`）。
- 二级菜单支持返回上一级与取消，全程不离开输入行。

## 5. 技术实现

### 5.1 新增模块

新建 `cli_palette.py`，基于 prompt_toolkit `Application` 实现一个组合式输入界面：

- 顶部区域：命令面板（`conditional` container，仅当输入以 `/` 开头时显示）。
- 底部区域：原聊天输入行（`prompt_toolkit` buffer）。
- 一个 `Application` 同时承载输入行与面板，实现"输入行 + 面板一体"，无独立界面切换。

### 5.2 数据源

- 命令名/描述：`slash_commands.COMMAND_DESCRIPTIONS`（统一列出，不分主人/公共）。
- 参数补全：`slash_commands.COMMAND_META` 的 `arg_completions`；`/model` 动态从模型缓存（`_MODEL_ARG_CACHE`）补全。
- 多步命令集合：沿用 `_MULTI_STEP_COMMANDS`，避免误发裸命令。

> 与 WebUI 斜杠命令面板同源（`slash_commands.list_commands()`），保证一致性。

### 5.3 cli.py 集成

- `run()` 输入循环改用 `CommandPalette` 替代 `PromptSession`。
- 保留 `_dispatch_slash_command` 作为命令执行入口（多步命令展开后在此分发）。
- 无 prompt_toolkit 时回退 `input()`（现有降级路径保留）。
- **欢迎屏（纳西妲 ASCII 艺术、口号、分隔横幅、命令提示、问候语）全部保留，不可替换，仅作必要优化**（如提示文案与面板交互保持一致）。

### 5.4 样式

- 沿用 `cli_menu.py` 的 `_MENU_STYLE` 与 `_C` 徽标配色（叶子绿 `LEAF`、`DGREEN`、`LGREEN` 等）。
- 面板背景与整体聊天界面一致，无割裂感。

## 6. 边界处理

- 面板打开时 `Enter` 走命令执行；面板关闭时 `Enter` 走普通消息发送。
- `Esc` 取消多步命令时不误发裸 `/model` 等（沿用 `_MULTI_STEP_COMMANDS` 判定）。
- `//` 仍作为转义斜杠发普通消息。
- 命令行窗口过小时面板自适应收缩，不溢出。
- 无 prompt_toolkit 环境（旧安装包）优雅降级到 readline/纯 `input()`。

## 7. 测试

- 单元测试：面板过滤逻辑、分组渲染、多步命令展开、Esc 取消不误发裸命令。
- 集成测试：`_dispatch_slash_command` 对多步命令的完整展开路径。
- 覆盖现有 `tests/test_cli_multistep.py`、`tests/test_cli_menu.py` 相关用例。

## 8. 非目标

- 不引入 Textual 或其他 TUI 框架。
- 不改动主进程命令处理逻辑（`SlashCommandHandler`）。
- 不做全屏命令中心/分类侧栏（避免"太丑/割裂"风险）。
